## Root causes and corrections

1. Payment capture did not call pickup assignment. Both payment verification and webhook capture now trigger logistics best-Driver assignment best-effort without rolling back a valid capture.
2. Order creation did not select an active navigable Facility. It now preserves a valid requested Facility or selects an active navigable one.
3. Facility transit updated state but did not open directions. The action now calls the Maps directions helper with the assigned Facility.
4. Driver detail mapping omitted the order number. The handoff card now shows the visual QR and order number.
5. Facility intake had no Order ID resolver. The new preview/receive endpoints re-use the same active-employee, assigned-Facility, status, active-QR code, duplicate, and atomic-receipt checks.
6. Facility cards used non-wrapping rows. The new layout contains badges and status text with flex shrink/wrap rules.
7. Parcel ID was mistakenly a required user input. It is now optional in the contract, hidden in mobile, and generated internally when absent.
8. QC was manager-only in mobile, API, service, and database function. The active Facility Staff capability now applies at all four layers while preserving Facility and processing invariants.
9. QC success did not call delivery auto-assignment. It now triggers logistics best-Driver assignment best-effort after the audited QC transition.
10. Delivery proof exposed only camera capture. The Driver can now take a photo or choose one from the phone; unavailable-camera and permission failures give a direct recovery path.

## Remaining limitations
